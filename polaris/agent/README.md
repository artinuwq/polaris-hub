# Polaris Agent

Лёгкий read-only агент мониторинга для Polaris Hub. Один Python-файл на
стандартной библиотеке: **без pip, venv, git и компиляции**. Сам открывает
исходящее HTTPS-соединение к Hub — Hub никогда не ходит на сервер по SSH.

```
Server → polaris-agent.py --HTTPS--> Polaris Hub API → Servers → Attention
```

## Установка

Команду берите в Hub UI: **Servers → Add Server** (токен одноразовый).

```bash
curl -fsSL https://raw.githubusercontent.com/artinuwq/polaris-hub/main/install.sh | \
  sudo bash -s -- agent --hub https://<HUB_DOMAIN> --token <REGISTRATION_TOKEN>
```

Установщик агента **не вызывает apt, не клонирует репозиторий и не ставит
пакеты**. Ему нужен только `python3` 3.7+. Что он делает:

1. проверяет, что на сервере есть хотя бы ~40 МБ свободной памяти;
2. скачивает один файл в `/opt/polaris-agent/polaris-agent.py`;
3. регистрируется в Hub, конфиг — `/etc/polaris-agent/config.json` (`0600`);
4. ставит systemd-сервис `polaris-agent-monitor` с жёсткими лимитами;
5. записывает в `config.json` адрес `update_url` — откуда агент берёт обновления (см. ниже).

Лимиты сервиса: `Nice=19`, `IOSchedulingClass=idle`, `CPUQuota=5%`,
`MemoryMax=64M`, `TasksMax=8`, `OOMScoreAdjust=800` (при нехватке памяти
ядро убьёт агента, а не ваш сервер), перезапуск не чаще раза в 30 секунд
и не больше 5 раз за 10 минут — crash-loop невозможен.

Мониторить systemd-сервисы: добавьте `--services nginx,docker`.
Если GitHub недоступен — `--agent-url <ссылка на polaris-agent.py>`.

## Вручную

```bash
python3 polaris-agent.py once                      # метрики в stdout, без сети
python3 polaris-agent.py register --hub https://hub.example --token plr_reg_xxx \
  --services nginx --config ./config.json
python3 polaris-agent.py run --config ./config.json --verbose
```

## Что делает

* `register` — меняет одноразовый токен на постоянные credentials.
* `run` — heartbeat (по умолчанию каждые 30 с) и метрики (каждые 60 с):
  CPU, RAM, диски, сеть, uptime, статусы systemd-юнитов. Hub может
  попросить реже, но не чаще 15 с / 30 с.
* Данные берутся из `/proc` и одного вызова `systemctl is-active` на все
  юниты сразу. Постоянных потоков и дочерних процессов нет.
* Нет входящих соединений. Hub не может запускать на сервере команды: он присылает только данные
  (настройки) и просьбу «обновись» — подробности ниже.
* При недоступном Hub — экспоненциальная пауза до 5 минут, без падения.
* Только Linux (читает `/proc`).

## Настройки из Hub

**Servers → сервер → Настройки агента**: список systemd-сервисов и интервалы heartbeat/метрик.
Агент получает их в ответе на ближайший heartbeat (до ~30 с), проверяет теми же правилами, что и локальный
конфиг (имена юнитов, нижние пороги 15 с / 30 с), применяет без перезапуска и запоминает в
`/var/lib/polaris-agent/remote.json`. Пока в Hub настройки не сохранялись, агент работает по `config.json`.

## Обновление

В карточке сервера показывается версия агента и «доступна X», если в клоне, на котором стоит Hub, лежит
версия новее. Версия — это `__version__` в `agent/polaris-agent.py`: поменяли цифру, запушили, обновили Hub —
агенты предлагают обновиться. Кнопка **«Обновить агент»** (или **«Обновить все»** в списке серверов):

1. Hub в ответе на heartbeat передаёт агенту только флаг «обновись» — **ни адреса, ни файла, ни хеша**.
2. Агент скачивает файл с `update_url` из своего `config.json` (https, адрес зашит при установке и из Hub
   не меняется), разбирает его (`ast.parse`, наличие `__version__`) и сравнивает версию: ставится только
   строго более новая. Файл кладётся в `/var/lib/polaris-agent/staged/`, агент завершается с кодом 75.
3. systemd перезапускает сервис, и **root-шаг** `ExecStartPre=+ … apply-update` подменяет
   `/opt/polaris-agent/polaris-agent.py`, оставляя прежний файл как `polaris-agent.py.prev`. Сам агент
   (пользователь `polaris-agent`) на запись в `/opt` прав не имеет. Root-шаг не доверяет каталогу
   состояния: читает файл без перехода по symlink и проверяет его заново.
4. Новая версия подтверждает запуск первым успешным heartbeat. Если она не вышла на связь за два запуска,
   следующий запуск автоматически возвращает `.prev` (итог «откат»).
5. Итог (`updated` / `current` / `failed` / `rollback`) уходит в Hub и показывается в карточке сервера.

Доверие: тот, кто может писать в репозиторий по адресу `update_url`, получает возможность запускать код
агента на всех ваших серверах (под пользователем `polaris-agent`), поэтому защитите репозиторий (2FA, защита
ветки). Взлом одного Hub этого не даёт: адрес репозитория он изменить не может. Отключить удалённое обновление
на конкретном сервере: `"remote_update": false` в `/etc/polaris-agent/config.json`.

Если `update_url` не задан (агент установлен со своей копией файла и не из GitHub) или unit без root-шага —
обновление завершится итогом «failed» с причиной. Чинится повторным запуском `install.sh agent`.

## Удаление

`uninstall.sh` из корня репозитория снимает сервис, удаляет
`/opt/polaris-agent`, `/etc/polaris-agent`, `/var/lib/polaris-agent` и пользователя `polaris-agent`.

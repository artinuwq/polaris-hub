# API для агента (Athena)

Эти ручки нужны, чтобы внешний агент мог работать с Polaris: читать задачи и календарь и создавать задачи.
Сейчас доступны **задачи** и **календарь (только чтение)**.

## Подключение

1. В приложении: **Настройки → Агент → Сгенерировать токен**. Токен показывается один раз — скопируйте его.
2. Адрес API: `https://<ваш-домен>/api/athena` (в настройках на вкладке «Агент» есть кнопка «Копировать адрес»).
3. Каждый запрос (кроме `/health`) должен содержать токен в одном из заголовков:

```
Authorization: Bearer <токен>
X-API-Token: <токен>
```

Токен хранится на сервере только в виде хеша. «Перевыпустить» делает прежний токен недействительным, «Отозвать» отключает доступ совсем.
Если на сервере задана переменная `API_TOKEN`, она работает как запасной вариант, пока токен не создан в настройках.

## Общие правила

| Что | Формат |
|---|---|
| Дата | `YYYY-MM-DD`, например `2026-11-01` |
| Время | `HH:MM` (24 часа), например `18:30` |
| Время сервера | даты и «сегодня» считаются по часовому поясу сервера |
| Пагинация | `limit` (1–200, по умолчанию 50) и `offset` |
| Ответ | JSON |

Коды ответов: `200` — успех, `201` — создано, `401` — нет или неверный токен, `404` — не найдено, `422` — ошибка в параметрах. В теле ошибки поле `detail` объясняет, что именно не так:

```json
{"detail": "date: ожидается формат YYYY-MM-DD, получено «31.10.2026»"}
```

## Служебные

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | Без токена. `{"status":"ok","service":"polaris","token_configured":true}` |
| GET | `/auth/verify` | С токеном. `{"valid":true}`, иначе `401` |

## Задачи

### Поля задачи

| Поле | Тип | Значения |
|---|---|---|
| `id` | строка | идентификатор |
| `title` | строка | название |
| `description` | строка | описание |
| `date` | строка | срок `YYYY-MM-DD` или `""` |
| `time` | строка | время `HH:MM` или `""` |
| `priority` | строка | `fire` (срочно), `important` (важно), `normal`, `someday` |
| `status` | строка | `todo`, `in-progress`, `waiting`, `done` |
| `energy` | строка | `quick` (быстро), `medium`, `large` (долго) |
| `repeat` | строка | `never`, `daily`, `weekly`, `monthly`, `yearly`, `custom` |
| `tags` | список строк | теги без `#` |
| `project` | строка | название проекта |
| `checklist` | список | `[{"text": "...", "done": false}]` |
| `important` | bool | вычисляется: приоритет `fire`/`important` **и** задача не выполнена |
| `created_at`, `updated_at`, `done_at` | строка | время в ISO |

### GET `/tasks/important`

Невыполненные задачи с приоритетом «срочно» или «важно», по срочности. Параметры: `limit`, `offset`.

```bash
curl -H "Authorization: Bearer $TOKEN" "$URL/tasks/important"
```

### GET `/tasks`

Все задачи. По умолчанию без выполненных. Список отсортирован **по срочности**: сначала задачи с ближайшей датой (по времени, затем по приоритету), потом задачи без даты.

| Параметр | Описание |
|---|---|
| `status` | `active` (по умолчанию — все, кроме выполненных), `all`, либо один статус: `todo`, `in-progress`, `waiting`, `done` |
| `priority` | `fire`, `important`, `normal`, `someday` |
| `project` | название проекта (без учёта регистра) |
| `tag` | тег (без учёта регистра, `#` можно не писать) |
| `date_from`, `date_to` | диапазон дат; задачи без даты в такую выборку не попадают |
| `limit`, `offset` | пагинация |

Ответ:

```json
{
  "items": [ { "id": "…", "title": "Сдать отчёт", "priority": "fire", "date": "2026-11-01", "time": "18:30", "important": true, "…": "…" } ],
  "total": 12,
  "limit": 50,
  "offset": 0
}
```

`total` — сколько задач подошло под фильтр (до пагинации).

### GET `/tasks/{id}`

Одна задача. `404`, если такой нет.

### POST `/tasks`

Создать задачу. **Обязателен только `title`**, всё остальное по желанию.

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" "$URL/tasks" -d '{
  "title": "Сдать отчёт",
  "description": "Квартальный",
  "date": "2026-11-01",
  "time": "18:30",
  "priority": "fire",
  "energy": "quick",
  "tags": ["work"],
  "project": "Polaris",
  "checklist": ["черновик", "правки"]
}'
```

| Поле | По умолчанию |
|---|---|
| `description`, `date`, `time`, `project` | пусто |
| `priority` | `normal` |
| `energy` | `medium` |
| `repeat` | `never` |
| `status` | `todo` |
| `tags`, `checklist` | пустые списки |

Ответ `201` — созданная задача. Если указанный `project` уже существует, подставляется его написание и цвет. Теги очищаются от `#` и дублей (до 20 штук), в чеклисте до 50 пунктов.

## Календарь (только чтение)

Календарь собирает в одном месте записи из разных разделов. Каждая запись имеет тип (`type`):

| Тип | Что это |
|---|---|
| `event` | событие (встреча и т. п.) |
| `task` | задача, у которой стоит дата |
| `reminder` | напоминание по задаче |
| `payment` | регулярный платёж |
| `subscription` | подписка |

### Поля записи

| Поле | Описание |
|---|---|
| `id`, `type`, `type_label` | идентификатор, тип и его русское название |
| `title`, `description` | название и описание. Для платежей `title` — это название платежа без суммы |
| `date`, `time`, `end_time` | дата, время начала и конца (`""`, если не заданы) |
| `all_day` | `true`, если время не указано |
| `priority`, `status`, `project`, `tags` | как у задач |
| `important` | `true` для срочных и важных невыполненных. **Все события (`event`) считаются важными** |
| `source`, `source_id` | откуда запись и её id. Для задач `source_id` — это id для `GET /tasks/{id}` |
| `amount`, `currency` | сумма и валюта — только у платежей и подписок, у остальных `null` и `""` |

Записи отсортированы по дате, затем по времени. Записи без времени идут после записей с временем.

### Общие параметры фильтрации

| Параметр | Описание |
|---|---|
| `types` | типы через запятую, например `event` или `event,payment`. Пусто — все типы |
| `important` | `true` — только важные |
| `include_done` | `true` — показывать и выполненные задачи (по умолчанию скрыты) |

### GET `/calendar/day`

Всё на конкретный день: события, задачи с этой датой, напоминания, платежи и подписки. Параметр `date` обязателен.

```bash
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/day?date=2026-11-05"
```

```json
{
  "date": "2026-11-05",
  "total": 2,
  "events": [
    { "type": "event", "title": "Созвон", "time": "10:00", "important": true, "…": "…" },
    { "type": "payment", "title": "Yandex плюс", "amount": 449.0, "currency": "RUB", "all_day": true, "…": "…" }
  ]
}
```

### GET `/calendar/month`

Весь месяц, сгруппированный по дням. Параметры: `year`, `month` (1–12). В ответе только дни, в которых что-то есть.

```bash
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/month?year=2026&month=11"
```

```json
{
  "start": "2026-11-01",
  "end": "2026-11-30",
  "total": 8,
  "days": [
    { "date": "2026-11-03", "events": [ { "…": "…" } ] },
    { "date": "2026-11-08", "events": [ { "…": "…" } ] }
  ]
}
```

### GET `/calendar/upcoming`

Следующие `days` дней, считая сегодняшний (по умолчанию 30, максимум 90), сгруппировано по дням. Сегодняшние записи, время которых уже прошло, не показываются; записи на весь день остаются. Формат ответа такой же, как у `/calendar/month`.

```bash
# все, включая платежи и задачи на ближайшие 30 дней
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/upcoming?days=30"
# только важное на 7 дней
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/upcoming?days=7&important=true"
```

### GET `/calendar/next`

«Что ближайшее»: одним списком по времени, без группировки. Смотрит на 60 дней вперёд. Параметр `limit` (1–50, по умолчанию 5).

```bash
# ближайшие 3 события
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/next?limit=3&types=event"
# ближайший платёж
curl -H "Authorization: Bearer $TOKEN" "$URL/calendar/next?limit=1&types=payment,subscription"
```

```json
{ "total": 3, "events": [ { "type": "event", "title": "Созвон", "date": "2026-11-04", "time": "10:00", "…": "…" } ] }
```

`total` — сколько всего записей подошло под фильтр в этом окне; в `events` вернётся не больше `limit`.

## Типичные запросы агента

| Задача | Запрос |
|---|---|
| Что сейчас важно | `GET /tasks/important` |
| Все активные задачи на эту неделю | `GET /tasks?date_from=2026-11-02&date_to=2026-11-08` |
| Что на завтра (всё: события, задачи, платежи) | `GET /calendar/day?date=2026-11-04` |
| Ближайшее событие | `GET /calendar/next?limit=1&types=event` |
| Только важные события на 30 дней | `GET /calendar/upcoming?days=30&types=event&important=true` |
| Какие платежи в ноябре | `GET /calendar/month?year=2026&month=11` и выбрать `type` = `payment` или сразу `&types=payment,subscription` |
| Добавить задачу с дедлайном | `POST /tasks` с `title`, `date`, `time` |

## Ограничения (на сегодня)

- Агент может **создавать** задачи, но пока не может их менять, завершать и удалять.
- Календарь доступен только для чтения. Создать событие через API нельзя.
- Напоминания в календаре показываются по одному на задачу (ближайшее), хотя в приложении их может быть несколько.
- Повторяющиеся задачи (`repeat`) в календаре раскрываются по датам, а в `/tasks` остаются одной записью.

## Управление токеном (для владельца, не для агента)

Эти ручки работают из приложения под вашим входом, токен агента к ним доступа не даёт.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/agent` | состояние токена (сам токен не возвращается) |
| POST | `/api/agent/token` | создать новый токен; возвращается один раз, прежний перестаёт работать |
| DELETE | `/api/agent/token` | отозвать токен |

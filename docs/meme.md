# Polaris Meme

Личная библиотека изображений: раздел в Mini App + поиск и отправка через Telegram Inline Mode
(`@бот спокойной ночи`). Файлы лежат в **Polaris Storage** (bucket `polaris-meme`, ключи `memes/<id>.<ext>`),
метаданные — в основной БД Polaris (таблица `memes`, миграция `012_create_meme.sql`).

## Включение

1. `STORAGE_ENABLED=true` и рабочий Storage (см. `storage.md`). Без него список открывается, но добавлять и показывать файлы нельзя (503).
2. В @BotFather: `/setinline` для бота и текст-подсказка (например «поиск картинки»). **Без этого Telegram не присылает боту inline-запросы.**
3. Inline открыт только для `TELEGRAM_ADMIN_IDS` (если список пуст — закрыт для всех).
4. Рекомендуется: создать закрытый чат или канал, добавить туда бота (в канале — администратором с правом публикации),
   открыть страницу Polaris Meme → шестерёнка → вписать id чата → «Проверить» → «Сохранить».
   Настройка хранится в БД Polaris и действует сразу, без перезапуска; веб и бот читают её оба.
   `MEME_CACHE_CHAT_ID` в `.env` остаётся значением по умолчанию (настройка в меню важнее).
5. Необязательно: `WEBAPP_URL` с публичным `https://` — запасной путь для JPEG, пока у картинки нет file_id (см. ниже).

## Меню настроек (шестерёнка на странице Meme)

- **Чат для inline-кэша** — id (`-100…`) или `@username`; «Проверить» убеждается, что бот видит чат и может писать (пишет сообщение и удаляет);
  пустое значение возвращает режим «в личку админу».
- **Inline-кэш** — сколько картинок уже готово к отправке из Telegram; «Обновить кэш» получает `file_id` для остальных порциями
  (например, для добавленных до настройки чата или при смене бота). Сменили чат — старые `file_id` продолжают работать.

API меню: `GET/PUT /api/meme/settings`, `POST /api/meme/settings/test`, `POST /api/meme/settings/sync`.

## Как картинка попадает в чат

Storage режет объект на чанки (`*.part`), это внутренняя кухня. Наружу всегда уходит целый оригинал:
`StorageCore.stream()` скачивает чанки, проверяет размер и SHA-256 каждого и итоговый хеш; сервис склеивает и сверяет хеш с записью.

- **Основной путь.** Сразу при добавлении через раздел Meme веб-процесс отправляет картинку в Telegram как обычное фото
  (GIF — как анимацию) основным ботом, получает `file_id` и сохраняет его в записи (`telegram_ready: true`).
  Куда уходит копия: в чат кэша из меню Meme или `MEME_CACHE_CHAT_ID` (закрытый чат/канал, где состоит бот; сообщения остаются) либо, если он не задан,
  вам в личку, а служебное сообщение сразу удаляется. Результаты в inline идут по `file_id`
  (`InlineQueryResultCachedPhoto` / `CachedGif`): быстро, без URL и без повторной загрузки.
  Storage остаётся источником правды с байтами оригинала; Telegram-копия пережата Telegram и нужна только для доставки.
- **Если Telegram при добавлении не ответил** (сеть, нет чата) — запись всё равно сохраняется. Тогда бот сам получит `file_id`
  при первом показе в поиске: заберёт оригинал у веб-процесса по подписанной ссылке на `127.0.0.1`, проверит SHA-256 и отправит
  в тот же чат. За один запрос «прогревается» не больше 3 картинок и не дольше ~6 с, остальные — при следующих запросах.
- **Запасной путь** (пока нет `file_id`): `InlineQueryResultPhoto` с подписанным https-URL — только JPEG ≤ 5 МБ и только при https `WEBAPP_URL`.
- Ссылки подписаны HMAC от секрета Polaris, относятся к одной записи, живут 1 час и в своём пространстве имён
  (токен Meme не открывает `/api/storage/download` и наоборот). Id объектов и чанков Storage в ссылках и ответах не появляются.

## API (`/api/meme`, только админ; `media/{token}` — по подписи)

| Метод | Путь | |
|---|---|---|
| GET | `/api/meme?q=&tag=&limit=&offset=` | поиск по названию, тегам, описанию; `total`, `next_offset`, `tags` |
| POST | `/api/meme?title=&tags=a,b&description=&filename=` | тело — байты файла; 409 при дубле (`existing_id`), 422 для не-изображений |
| GET / PATCH / DELETE | `/api/meme/{id}` | запись / `{title?, tags?, description?}` / удалить запись и файл из Storage |
| GET | `/api/meme/media/{token}` | оригинал с настоящим Content-Type |

Поиск: все слова запроса должны найтись в названии, тегах или описании; регистр и «ё/е» не важны; название весит больше тегов, теги — больше описания.

## Ограничения

JPEG, PNG, статичный WebP, GIF; до 10 МиБ, `ширина+высота ≤ 10000`, соотношение сторон ≤ 20:1 (лимиты Telegram).
Дубли определяются по SHA-256 содержимого. Миниатюр нет: в Mini App показываются оригиналы.
Файл, удалённый напрямую из раздела Files, останется записью без картинки; удаление записи при этом работает.
